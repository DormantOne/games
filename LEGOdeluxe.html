Assembly instructions

Basic / original compatible mode

Classic rectangular bricks. Legacy models use y in brick layers (one brick = three plates). New version 2 models use y in plate units. Select Basic to limit generation to ordinary bricks.

Advanced / mechanical catalog

Real wheel assemblies, plates, tiles, slopes, Technic bricks, locking hinges, ball sockets and articulated train-style couplings. Paired joints use explicit mating geometry in a neutral pose. Ordinary parts use a stud grid; wheels attach to defined connectors rather than pretending to be rectangular bricks.

Technic & robotics workbench

Use long perforated Technic bricks freely for frames, rails and joint interfaces. Axles, pins, gears, liftarms and larger wheels are now rendered as connector-mounted parts. Powered Up motors and electronic hubs remain manual engineering plan items. They are included in sourcing but are not certified as connected geometry. The compiler never treats an arbitrary box as a valid motor mount or gear train.

Paired joint catalog

Joint bodies and connector protrusions are schematic. A mating-pair check is not a physical mesh, tolerance or range-of-motion certification. Turntables and powered components remain manual engineering items; liftarms have nominal hole geometry.

Engineering checklist

Specify axle line, compatible holes and pins, axle length, gear mesh, mount points, moving clearance, torque/load, cable route, hub access and power compatibility. For powered vehicles, specify a transmission: free-spinning 4624 wheel holders alone do not provide motor drive.

One-shot design

One prompt, one complete model. The designer defines target geometry, writes and executes code, generates candidate assemblies, scores them and checks the best design. Tool execution is performed by the external model, not this browser. Inspect the resulting build at each milestone.

Always-on robustness standard

Function and strength before styling. Use the simplest robust mechanism, supported joints, short load paths, retained axles and a stiff frame. Part budgets are guidance, not quotas. A smaller sturdy build beats a large fragile one. Compiler acceptance and animation are not proof of physical strength.

Tool-enabled optimization

One user action, multiple internal computational passes. The prompt includes executable Python and the exact studio validator. Use a model with a Python or coding tool. The browser never executes code returned by the model.

Compile returned JSON

How one-shot design works

With tools enabled, the LLM executes Python and the original compiler validator, searches candidates and corrects failures before output. The response is one final model, not one inference. The studio milestones expose the resulting physical build sequence without requesting another response. Optional repair is only for a failed import. Every accepted response is a complete replacement snapshot, never a patch.
